    What is inside

    Two-tier cache
    Exact matches return in microseconds from Redis. Everything else goes through embeddings and a Qdrant vector search.
    Safety guard
    Two prompts can be near-identical to an embedding and still ask opposite things: "15% of 200" versus "25% of 200", "safe" versus "not safe". Numbers and negations must agree before any answer is reused.
    Verifier agent
    Matches just under the threshold are checked by a cheap model that decides whether both questions want the same answer. If it fails, the request goes to the model.
    Governor agent
    Watches guard rejections and verifier approvals, then tightens or loosens the threshold one step at a time, inside hard bounds, and keeps a readable journal.
    Cost-aware router
    Model "auto" sends simple prompts to the cheap tier and hard ones to the strong tier.
    Privacy and tenants
    Emails, card numbers and phone numbers are redacted before embedding or storage. Each tenant and system prompt gets its own cache namespace.
    Observability
    Prometheus metrics and a Grafana dashboard for hit rate, latency by status, tokens and dollars saved.
    Agent tools
    /agent/tools publishes function-calling schemas so other AI agents can read stats, invalidate entries or tune the cache.

    Run it

    git clone https://github.com/YOUR-USERNAME/semanticache
cd semanticache
cp .env.example .env
docker compose up --build      # API :8000, Grafana :3000
python scripts/simulate.py     # watch hits appear

    No API key needed: without one, it uses a mock model and a local embedder. Add OPENAI_API_KEY to go live. Point any OpenAI SDK at http://localhost:8000/v1.
